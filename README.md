# Seller CRM 

Бэкенд приложение для управления продавцами и их транзакциями.
Система позволяет вести учет продавцов, фиксировать транзакции и анализировать эффективности продаж. 

## Функциональность

Управление продавцами - создание, просмотр, обновление и удаление. 
Управление транзакциями - создание и просмотр транзакций по продавцам.
Аналитики - определение самого продуктивного продавца за период, поиск продавцов с низкими показателями продаж и нахождение лучшего периода активности для конкретного продавца 

## Зависимости

- Java 21
- Spring Boot 3.5.14 - фреймворк для REST API
- Spring Data JPA - работа с базой данных
- PostgreSQL - основная база данных
- H2 - база данных для разработки и тестов 
- Lombok - устраняет шаблонный код (геттеры, сеттеры, конструкторы)
- Validation - валидация входящих данных 
- JUnit 5 + Mockito - тестирование 

## Сборка и запуск

Для запуска c H2: 
```bash
./gradlew bootRun --args='--spring.profiles.active=dev'
```

Для запуска с PostgreSQL создать базу данных и запустить через Docker Compose:
```bash
docker-compose up
```
Приложение работает на порту **http://localhost:8080**

## Примеры использования API

### Создать продавца

```
POST /api/sellers
Content-Type: application/json

{
    "name": "Иван Иванов",
    "contactInfo": "ivan@mail.ru"
}    
```

### Получить всех продавцов

```
GET /api/sellers
```

### Получить продавца по ID

```
GET /api/sellers/1
```

### Обновить продавца

```
PUT /api/sellers/1
Content-Type: application/json

{
    "name": "Иван Иванов",
    "contactInfo": "ivannew@mail.ru"
}
```

### Удалить продавца

```
DELETE /api/sellers/1
```

### Создать транзакцию

```
POST /api/transactions
Content-Type: application/json

{
    "sellerId": 1,
    "paymentType": "CARD",
    "amount": 1000
} 
```

### Получить все транзакции продавца

```
GET /api/transactions/seller/1
```

### Лучший продавец за период

```
GET /api/analytics/top-seller?period=MONTH 
```

Доступные периоды: **DAY**, **MONTH**, **QUARTER**, **YEAR**

### Продавцы с суммой меньше указанной

```
GET /api/analytics/sellers-below?period=MONTH&amount=100000
```

### Лучший период активности продавца

```
GET /api/analytics/best-period/1
```

## Алгоритм лучшего периода

Для поиска лучшего периода активности продавца реализован алгоритм на основе разрывов между транзакциями. 

Транзакции группируются в периоды активности - если разрыв между соседними транзакциями превышает адаптивный порог, начинается новый период.
Порог вычисляется как **max(24 часа, 75 перцентиль разрывов * 2)** - это позволяет учитывать индивидуальный ритм каждого продавца.

Возвращается период с наибольшим количеством транзакций. 

Алгоритм неидеален и требует доработки.

**Известные ограничения**: 
- При равномерной активности продавца алгоритм может вернуть весь диапазон транзакций как один период.
