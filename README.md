# Seller CRM

Приложение для управления продавцами и их транзакциями.
Система позволяет вести учет продавцов, фиксировать транзакции и анализировать эффективности продаж.

Сайт доступен по адресу: **http://104.248.134.131:8080**

## Функциональность

Управление продавцами - создание, просмотр, обновление и удаление. Реализовано мягкое удаление — данные сохраняются в базе, просто помечаются как удалённые.

Управление транзакциями - продавцы сами фиксируют свои продажи через личный кабинет. Администратор видит все транзакции с фильтрацией по продавцу.

Кошелёк - у каждого продавца есть внутренний кошелёк, баланс которого пополняется автоматически при каждой новой транзакции. Доступна история пополнений.

Аналитика - определение самого продуктивного продавца за период, поиск продавцов с низкими показателями продаж и нахождение лучшего периода активности для конкретного продавца.

Авторизация - два типа пользователей. Администратор управляет всей системой: видит всех продавцов, все транзакции, полную аналитику. Продавец видит только свои данные, транзакции, баланс кошелька и личную аналитику.

Личный кабинет продавца - история транзакций с фильтрацией по типу оплаты и дате, статистика по месяцам, лучший период активности, возможность обновить контактные данные.

## Зависимости

- Java 21
- Spring Boot 3.5.14 - фреймворк для REST API
- Spring Security - авторизация и управление сессиями
- Spring Data JPA - работа с базой данных
- Thymeleaf - серверный рендеринг страниц
- PostgreSQL - основная база данных
- H2 - база данных для разработки и тестов
- Lombok - устраняет шаблонный код (геттеры, сеттеры, конструкторы)
- Validation - валидация входящих данных
- Docker, Docker Compose - контейнеризация и деплой

## Сборка и запуск

Для запуска c H2:
```bash
./gradlew bootRun --args='--spring.profiles.active=dev'
```

Для запуска с PostgreSQL создать базу данных и запустить через Docker Compose:
```bash
docker-compose up --build
```

Приложение работает на порту **http://localhost:8080**

При первом запуске автоматически создаётся аккаунт администратора — логин `admin`, пароль `admin`.

## Алгоритм лучшего периода

Для поиска лучшего периода активности продавца реализован алгоритм на основе разрывов между транзакциями.

Транзакции группируются в периоды активности - если разрыв между соседними транзакциями превышает адаптивный порог, начинается новый период.
Порог вычисляется как **max(24 часа, 75 перцентиль разрывов * 2)** - это позволяет учитывать индивидуальный ритм каждого продавца.

Возвращается период с наибольшим количеством транзакций.

Алгоритм неидеален и требует доработки.

**Известные ограничения**:
- При равномерной активности продавца алгоритм может вернуть весь диапазон транзакций как один период.
